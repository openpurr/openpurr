Price experiments: test what your app should charge by showing customers new to the app different offerings, then comparing what each group buys. Also the dashboard in 17 languages, and a website in 17 languages with a savings calculator.

## What's new

**Price experiments (Lite)**
- **Experiments** in the dashboard, under Configuration: two to four variants, each an offering from your config with a share of new customers. The first variant is the control. Create a draft, start it, stop it; every change is in the audit log.
- **No app changes.** While an experiment runs, `Purchases.getOfferings()` returns the customer's variant as the `current` offering. Every other offering is still listed, so a paywall that asks for an offering by ID gets that offering.
- **Only customers new to the app take part:** an app user ID openpurr hasn't seen, or a customer first seen after the experiment started. Existing customers keep their price. Each person keeps their variant, across `logIn` too.
- **Results per variant:** customers, trials started and converted, paying customers, revenue and revenue per customer (USD, net of refunds), active subscriptions, MRR, churn, and what paying customers bought first, for production and sandbox purchases. Each variant shows the difference from the control and the chance that it's higher; it's called **likely better** or **likely worse** at 95%, once there's enough data.
- **Webhooks** for a customer in an experiment carry RevenueCat's `experiments` field, so existing handlers can attribute revenue to variants. The customer's page shows their experiments too.
- **Admin API and MCP:** `/admin/v1/experiments` creates, starts, stops and reads experiments, and the MCP tool `get_experiments` lists them with their results. `doctor` warns when a running experiment's offering is missing from the config.
- One experiment runs per project at a time. The [guide](https://github.com/openpurr/openpurr/blob/main/docs/price-experiments.md) covers setup, what the results count and the limits.

**Dashboard in 17 languages (Lite)**
- The back office speaks the website's 17 languages, including right-to-left Arabic. Pick one under **Your account → Language**, or leave it on Automatic to follow the browser.
- Dates, numbers, money and chart axes follow the language.

**Website**
- The home page, the migration page and the README in 17 languages.
- A savings calculator compared with RevenueCat ([openpurr.org/#savings](https://openpurr.org/#savings)), and the same table in the README.
- An interactive dashboard demo on the home page.
- The language menu closes on a click outside, Escape, or focus leaving it.

**Project**
- A code of conduct, issue templates and a pull request template. Contact: hello@openpurr.org.
- The Claude Code plugin's version now follows releases, and its `debug-purchase` skill knows about experiments.

## Upgrading

Lite deploys from `main`, so a deployment that follows `main` already has these changes. This release adds two database migrations (`0019_operator_locale`, `0020_experiments`), which the deploy workflow applies. If you deploy by hand, apply them first:

```sh
cd lite && pnpm db:migrate:remote
```

`openpurr doctor` reports a missing migration. No app changes are needed. Webhook handlers that ignore unknown fields need no changes either; the `experiments` field appears only for customers in an experiment.

The CLI is unchanged apart from its version:

```sh
npm install -g @openpurr/cli@0.3.0
```
