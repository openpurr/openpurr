The Standard edition: openpurr in Go and Postgres, for larger portfolios of apps, with deployment templates for Google Cloud, AWS and DigitalOcean. A move from Lite to Standard that needs no app update, and fixes to Lite found while building Standard.

## What's new

**Standard edition**
- **Everything Lite does**, as one container on Postgres: App Store and Google Play purchases and notifications, Play acknowledgement and polling, webhooks with retries and replay, the dashboard and admin API, 16 charts, price experiments, operator sign-in, roles, access tokens and the audit log, and the MCP server with OAuth.
- **The same behavior as Lite**, checked by a shared conformance suite (`spec/conformance`) that runs against both editions in CI over HTTP, with fake App Store and Google Play servers.
- **The same dashboard.** It follows the server's edition, and on Standard the Charts pages add a country filter.
- **Background work runs in the server:** webhook retries, exchange rates, Google Play's jobs and housekeeping, on a scheduler that is safe to run with several instances.
- The image is `ghcr.io/openpurr/openpurr-standard:0.4.0`. See [`standard/README.md`](https://github.com/openpurr/openpurr/blob/main/standard/README.md) for what isn't built yet (cohort charts) and how it differs from Lite.

**Deployment templates**
- OpenTofu modules in `infra/` for three clouds, each with a step-by-step guide:
  - **Google Cloud:** Cloud Run and Cloud SQL, with optional sign-in through Identity-Aware Proxy ([guide](https://github.com/openpurr/openpurr/blob/main/docs/standard-on-gcp.md)).
  - **AWS:** ECS on Fargate, RDS for PostgreSQL and an Application Load Balancer ([guide](https://github.com/openpurr/openpurr/blob/main/docs/standard-on-aws.md)).
  - **DigitalOcean:** App Platform and Managed PostgreSQL, usually the cheapest of the three ([guide](https://github.com/openpurr/openpurr/blob/main/docs/standard-on-digitalocean.md)).
- Each guide covers secrets, the domain, creating the owner, upgrades, backups and costs. The templates are tested in CI against mocked providers.

**Moving from Lite to Standard**
- **No app update**, provided your app points at a custom domain you own. Lite's Workers keep answering on your domains and forward every request to Standard, so apps, Apple and Google don't notice the switch.
- **New CLI commands:** `openpurr export` writes Lite's data to a bundle, Standard's `migrate import` loads it, and `openpurr migrate verify` compares the two deployments. Catch-up exports (`--since`) carry the changes made in the meantime, as often as you like before cutting over.
- **Keys and logins carry over:** secret keys, access tokens, passwords, authenticators and MCP connections keep working on Standard, as long as it has Lite's `OPERATOR_SECRET`.
- The [guide](https://github.com/openpurr/openpurr/blob/main/docs/migrating-from-lite-to-standard.md) covers each step, rolling back, and the few changes to hold off on while you move. The whole move runs end to end in CI.

**Fixes (Lite, and the same in Standard)**
- **App Store:** a signed payload whose signature isn't base64url gets a 4xx instead of a 500. A refund with no reason is stored as having none.
- **Google Play:** one misconfigured Play app no longer stops the others' scheduled work. Pub/Sub messages that aren't notifications are acknowledged instead of retried, and push tokens with a null header or claims are refused. Replacing a Play subscription refreshes the previous owner's CustomerInfo.
- **CustomerInfo:** a snapshot rebuilt while a purchase lands can no longer be saved stale.
- **Sign-in:** the account locks after 10 wrong authenticator or recovery codes, and one-time setup and recovery links can't be used twice. A bad grant note or an unreadable password hash gets a 4xx instead of a 500, and a negative page size is clamped.
- **Charts:** purchases at the same moment in a chain count once, purchases with no expiry stay out of renewal chains, and dates that don't exist are refused.
- **MCP and OAuth:** codes, refreshes and consent are each decided once, scopes aren't listed twice, a client metadata document that isn't a JSON object is refused, and long client names are shortened without splitting a character.

**Docs and website**
- [Moving from Adapty](https://github.com/openpurr/openpurr/blob/main/docs/migrating-from-adapty.md): replace the Adapty SDK with the Purchases SDK, and import App Store customers from Adapty's event export.
- [Where your 1% goes](https://openpurr.org/revenuecat-pricing/): an interactive estimate of what RevenueCat's revenue share pays for.

## Upgrading

Lite deploys from `main`, so a deployment that follows `main` already has these changes. This release adds one database migration (`0021_snapshot_ledger_version`), which the deploy workflow applies. If you deploy by hand, apply it first:

```sh
cd lite && pnpm db:migrate:remote
```

`openpurr doctor` reports a missing migration. No app changes are needed.

The CLI adds `export` and `migrate`:

```sh
npm install -g @openpurr/cli@0.4.0
```

Standard isn't recommended for production yet, as with Lite: try it on a test deployment first.
