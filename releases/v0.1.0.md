The first release of **openpurr Lite**: an open-source, self-hosted backend for in-app purchases and subscriptions that works with the official, unmodified RevenueCat SDKs. It runs on your own Cloudflare account, on Cloudflare's free plan: two Workers and a D1 database.

This is an early release. Expect changes before 1.0, and please report anything that breaks in [issues](https://github.com/openpurr/openpurr/issues).

## What's in it

**Purchases and entitlements**
- **App Store:** verified StoreKit 2 transactions, plus StoreKit 1 receipts through the App Store Server API, and a status refresh on restore.
- **Google Play:** every purchase is verified and acknowledged, and refunds are caught through voided-purchase polling.
- **Store notifications:** App Store Server Notifications V2 and Google Play Real-time Developer Notifications keep renewals, cancellations, grace periods, billing retries and refunds current.
- **SDK compatibility:** CustomerInfo, entitlements, offerings, subscriber attributes and intro-offer eligibility, in the shapes the SDKs expect.
- **Fast reads:** CustomerInfo snapshots answer most reads with a single database query.

**Projects**
- **Several titles in one deployment:** each title is a project with its own apps, entitlements, offerings, webhooks, secret keys and customers.
- **Config in the database:** the config is versioned, with history and one-step restore, and changes need no redeploy. The SDK picks them up within a minute.

**Webhooks**
- RevenueCat-shaped events, so existing RevenueCat webhook handlers work unchanged.
- Each event is signed with HMAC-SHA256, retried for about 72 hours, and can be replayed.
- Prices are converted to USD at each purchase date's European Central Bank rate.

**Dashboard**
- **Configuration:** apps, SDK keys, products, entitlements, offerings, webhook endpoints and projects. On a new deployment, it opens on adding your first app.
- **Customers:** search by app user ID, email or transaction ID, with full purchase history and promotional grants.
- **Charts:** 16 of them, including revenue, MRR, ARR, MRR movement, subscriptions, trials, churn, refunds and subscription status. Filter by project, app, store, product and environment, and export to CSV.
- **Team and security:**
  - sign-in with a password and optional authenticator codes;
  - roles (owner, admin, developer, viewer), optionally limited to some apps;
  - personal access tokens, secret keys for your backend, and an audit log.

**AI and command line**
- **MCP server at `/mcp`:** look up customers, explain why someone does or doesn't have an entitlement, read charts, grant access and edit the config. Works from Claude Code, and as a Claude.ai connector through OAuth 2.1.
- **CLI, `npx @openpurr/cli`:** setup checks (`doctor`), customers, grants, charts, webhooks, keys, the team, and `config pull` / `push`.
- **Claude Code plugin:** skills for deploying, App Store and Google Play setup, app integration, webhooks and debugging purchases.

**Running it**
- **Guided setup, `pnpm run setup`:** creates the database, deploys both Workers, sets the operator secret and creates your owner account.
- **Deploy on every push:** a GitHub Actions workflow for your fork, configured with repository secrets.
- **Backups:** `pnpm db:backup` exports the database, and D1 keeps 7 days of history on the free plan (30 on Workers Paid).
- **Free-plan checks:** rate limits per IP and per user, scheduled cleanup to keep storage down, and a database-size warning in `doctor`.

## Getting started

See [Getting started](https://github.com/openpurr/openpurr#getting-started) in the README. You need Node 22.12 or later, a Cloudflare account, and about ten minutes.

## Known limitations

- **Lite edition only.** The Standard edition (Go and Postgres on your own cloud) hasn't started.
- **Android extra traffic:** even with a proxy URL, the Android SDK sends diagnostics, paywall and ad traffic straight to RevenueCat. openpurr turns diagnostics off, but don't use RevenueCatUI paywalls or ads on Android.
- **Entitlement verification:** leave it at the SDK's default (off). Signed responses rely on RevenueCat's own key.
- **Customer data by app user ID:** anyone who knows an app user ID can read that customer's data through the public SDK key. Verified end-user identity is on the roadmap.
- **Device testing is still in progress:** full purchase runs with the iOS and Android purchase tester apps aren't finished yet.
